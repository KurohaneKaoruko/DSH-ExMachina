# DSH-ExMachina

> [!WARNING]
> 本预设尚未经过全面测试。不同模型、不同任务形态下的分派行为可能存在偏差；使用前请在受控任务上自行验证。

**DSH-ExMachina** 是 DeepSeek Harness（DSH）的一个智能体预设（agent preset）。安装后，该预设下的每个会话以同一个稳定的方式工作：先收拢任务边界与证据，再决定亲自执行还是分派子代理，最后裁决回流、收束交付。它不改变模型能力，只固定工作流程。

## 有什么

```text
.
├─ agent.cordis.yml              # 预设编排：standard 全量基座 + 机械智能 persona + 技能发现
├─ preset.yml                    # 花名册元数据
├─ install.ps1                   # 安装脚本
├─ skills/
│  ├─ exmachina-dispatch/
│  │  └─ SKILL.md                # 分工协议：选路 / 任务简报契约 / 职能卡 / 回流契约 / 裁决与收束
│  └─ exmachina-protocol/
│     └─ SKILL.md                # 协议层：证据分级 / 冲突裁决 / 变更 / 调试 / 审查 / 安全审计
└─ README.md
```

预设由三层构成：

| 层 | 载体 | 内容 | 进入上下文的时机 |
|----|------|------|------------------|
| 身份层 | `agent.cordis.yml` 的 persona 行 | 核心准则、最高优先级栈、分工方式骨架、输出契约 | 每轮请求，常驻 |
| 分工协议 | `exmachina-dispatch` 技能 | 选路表、六字段任务简报契约、七张职能卡、回流契约、裁决与收束流程 | 分派子代理前加载 |
| 协议层 | `exmachina-protocol` 技能 | 证据分级、冲突裁决、变更、调试、审查、安全审计的具体规则 | 调试 / 审查 / 变更 / 安全类任务前加载 |

### 核心准则（身份层常驻）

理性、平淡、机械、简洁、高效：

- **理性**：事实、推断、假设、决策严格区分；结论标注证据等级（A 直接证据 / B 高可信推断 / C 暂定假设 / D 待证猜测），置信度不得超过证据等级。
- **平淡**：无情绪修辞，无客套与说服性措辞。
- **机械**：同名任务走同一路径；边界 → 证据 → 行动 → 校验 → 收束。
- **简洁**：输出只保留可执行信息与必需上下文。
- **高效**：无依赖动作并行；最小可逆变更；不重复已完成的工作。

### 最高优先级（冲突时的裁决序）

1. **安全**：不执行无回退路径的不可逆动作；沙箱、审批与权限边界只可经正规审批穿越。
2. **诚实**：未知显式标注；失败直接陈述；不用流畅表述掩盖证据缺口。
3. **权限**：动作不超出任务边界与既有授权；被拒绝的路径即终止，不构造变体绕行。
4. **协议**：遵循分工协议与输出契约。

## 能做什么

- **常规编码工作**：基座继承自 DSH 官方 `standard` 预设——文件读写与检索、Shell、后台任务、目标、计划模式、上下文压缩、子代理、工作流全部保留，不做能力裁剪。
- **复杂任务组队**：多阶段开发任务被拆解为可独立验收的阶段，按职能卡（侦察 / 规划 / 编码 / 验证 / 审核 / 运维 / 文档）分派子代理，无依赖的分派并行执行。例如「给这个模块加缓存并保证不回归」会走 侦察 → 规划 → 编码 → 验证 的分派链。
- **小任务直达**：单点改动、一次检索可定论的任务不组建编制，指挥体直接完成；问候、翻译、总结类请求不触发分工流程。
- **结论可审计**：每条关键结论可追溯（结论 → 证据等级 → 证据位置）；子代理回流必须携带结论、证据、风险与未知，缺项按不合格处理并补收。
- **冲突显式裁决**：多个子代理结论冲突时不平均、不拍板，核对证据等级、要求反证或复验后裁决，并记录残余风险。

## 为什么这样设计

- **三层分离，协议按需加载**：选路表、职能卡、分级规则只在相关任务出现时进入上下文，身份层只留骨架。常驻开销低且系统提示前缀稳定（利于 KV 缓存复用），完整契约又不在需要时缺席。
- **实现与校验分离**：编码体与验证体 / 审核体不得合并到同一个子代理。实现者不自证，回流才能被独立采信。
- **任务简报必须自包含**：spawn 子代理看不到父会话历史；自包含简报（角色、验收标准、边界禁区、输入、交付格式、预算）是任务可验收的前提，也是并行分派互不干扰的前提。
- **保留 standard 全量基座**：本预设叠加的是工作方式而不是能力子集；裁剪工具会制造「协议要求分派、工具却不存在」的矛盾。
- **优先级写成裁决序**：安全 > 诚实 > 权限 > 协议。固定顺序而非并列口号，冲突时才有唯一答案。

## 安装

### 方式 A — 安装脚本

```powershell
git clone https://github.com/KurohaneKaoruko/DSH-ExMachina.git
cd DSH-ExMachina
.\install.ps1
```

脚本把预设复制到 `%USERPROFILE%\.dsh\.agent-presets\exmachina\`（已设置 `DSH_HOME` 时为 `%DSH_HOME%\.agent-presets\exmachina\`）。

### 方式 B — 手动复制

把本仓库全部内容复制到上面的目录即可（`README.md` 与 `install.ps1` 可选）。

### 验证

1. 重启 DSH 或新开会话，在预设选择器中确认出现「机械智能」。
2. 新开一个该预设的会话，确认工具目录包含 `subagent` 与 `subagent_fork`。
3. 交给它一个多阶段开发任务，观察是否先收拢边界、再按职能卡分派子代理。

### 卸载

删除 `%USERPROFILE%\.dsh\.agent-presets\exmachina\` 目录。已运行的会话保持其启动时的编排，不受影响。

## 依赖与边界

- 组合基座为 DSH 官方 `standard` 预设；`subagent` / `subagent_fork` 依赖宿主组合中的 subagents 注册表，预设只贡献委派工具与协议。
- `workflow` 与 `ralph` 仅在用户明确要求时使用，与运行时工具描述的门控一致。
- Codex / Claude Code 原生子代理行默认停用；需要时按 DSH 文档安装对应 Bundle 后取消对应行的 `disabled`。

# DSH-ExMachina

> [!WARNING]
> 本预设尚未经过全面测试。不同模型、不同任务形态下的分派行为可能存在偏差；使用前请在受控任务上自行验证。

**DSH-ExMachina** 是 DeepSeek Harness（DSH）的一个智能体预设（agent preset）。安装后，该预设下的每个会话以同一个稳定的方式工作：先收拢任务边界与证据，再编排子代理分工执行，最后裁决回流、收束交付。指挥体不亲自做工，只保留任务编排、用户交接、冲突管理与收束四项职责。

## 有什么

```text
.
├─ agent.cordis.yml              # 预设编排：standard 全量基座 + 指挥体 persona + 技能发现
├─ preset.yml                    # 花名册元数据
├─ install.ps1                   # 安装脚本（人类执行）
├─ skills/
│  ├─ exmachina-dispatch/
│  │  └─ SKILL.md                # 分工协议：选路与直达例外 / 波次编排 / 轮次让出 / 冲突管理 / 回流契约
│  └─ exmachina-protocol/
│     └─ SKILL.md                # 协议层：证据分级 / 冲突裁决 / 变更 / 调试 / 审查 / 安全审计
└─ README.md
```

预设由三层构成：

| 层 | 载体 | 内容 | 进入上下文的时机 |
|----|------|------|------------------|
| 身份层 | `agent.cordis.yml` 的 persona 行 | 核心准则、最高优先级栈、职责与分工、并行与等待、输出契约 | 每轮请求，常驻 |
| 分工协议 | `exmachina-dispatch` 技能 | 选路表、六字段任务简报契约、七张职能卡、回流契约、冲突管理与收束流程 | 分派子代理前加载 |
| 协议层 | `exmachina-protocol` 技能 | 证据分级、冲突裁决、变更、调试、审查、安全审计的具体规则 | 调试 / 审查 / 变更 / 安全类任务前加载 |

### 核心准则（身份层常驻）

理性、平淡、机械、简洁、高效：

- **理性**：事实、推断、假设、决策严格区分；结论标注证据等级（A 直接证据 / B 高可信推断 / C 暂定假设 / D 待证猜测），置信度不得超过证据等级。
- **平淡**：无情绪修辞，无客套与说服性措辞。
- **机械**：同名任务走同一路径；边界 → 证据 → 行动 → 校验 → 收束。
- **简洁**：输出只保留可执行信息与必需上下文。
- **高效**：无依赖动作并行；最小可逆变更；不重复已完成的工作。

### 最高优先级（冲突时的裁决序）

1. **安全**：不执行无回退路径的不可逆动作；沙箱、审批与权限边界只可经正规审批穿越。
2. **诚实**：未知显式标注；失败直接陈述；不用流畅表述掩盖证据缺口。
3. **权限**：动作不超出任务边界与既有授权；被拒绝的路径即终止，不构造变体绕行。
4. **协议**：遵循分工协议与输出契约。

## 能做什么

- **常规编码工作**：基座继承自 DSH 官方 `standard` 预设——文件读写与检索、Shell、后台任务、目标、计划模式、上下文压缩、子代理、工作流全部保留，不做能力裁剪。
- **分派优先**：可独立验收的实施性工作（侦察、规划、编码、验证、审查、运维、文档）默认分派子代理；直达仅限三类例外——纯交互澄清、单文件微操作、补收缺项时的现场核验。
- **多线并行与轮次让出**：无依赖的分派在同一轮并行发出并默认后台执行；分派即向用户交代编制并结束本轮等待回流，不轮询空等。等待期间用户新需求照常受理，并入调度表，与在途工作并行推进。
- **冲突预防与裁决**：每份子代理简报声明独占写入路径，同一文件的变更串行归口，构建、安装、发布等全局副作用同时至多一个子代理持有；回流触碰同一写入路径即冲突，核对证据后保留达标一路、缩窄边界重派另一路，记录裁决与残余风险。
- **结论可审计**：每条关键结论可追溯（结论 → 证据等级 → 证据位置）；子代理回流必须携带结论、证据、写入路径、风险与未知，缺项按不合格处理并补收。

## 为什么这样设计

- **指挥体不亲自做工**：主会话的上下文预算留给编排、交接与裁决；实施细节发生在子代理上下文里，随回流压缩，不占主会话。判断顺序固定：能分派 → 分派；不能独立验收 → 先收拢成可独立验收再分派。
- **后台分派 + 让出轮次**：分派调用立即返回，主会话在等待期保持可交互——用户布置新需求不必等在途工作完成；新需求与在途工作在同一张调度表（todo）上并行，完成通知由运行时推送，落定后统一收集裁决。
- **三层分离，协议按需加载**：选路表、职能卡、分级规则只在相关任务出现时进入上下文，身份层只留骨架。常驻开销低且系统提示前缀稳定（利于 KV 缓存复用），完整契约又不在需要时缺席。
- **实现与校验分离**：编码体与验证体 / 审核体不得合并到同一个子代理。实现者不自证，回流才能被独立采信。
- **任务简报必须自包含**：spawn 子代理看不到父会话历史；自包含简报（角色、验收标准、边界禁区、独占写入路径、输入、交付格式、预算）是任务可验收与并行互不干扰的前提。
- **保留 standard 全量基座**：本预设叠加的是工作方式而不是能力子集；裁剪工具会制造「协议要求分派、工具却不存在」的矛盾。
- **优先级写成裁决序**：安全 > 诚实 > 权限 > 协议。固定顺序而非并列口号，冲突时才有唯一答案。

## 安装

### 方式 A — 交给 DSH 自己安装（推荐）

把下面整段发给一个具备文件写入与运行时挂载能力的 DSH 会话（例如「创造模式」预设），由它完成安装与验证：

```text
请为本部署安装 DSH-ExMachina 预设：
1. git clone https://github.com/KurohaneKaoruko/DSH-ExMachina.git 到用户预设根下的 exmachina 目录：
   git clone https://github.com/KurohaneKaoruko/DSH-ExMachina.git "%DSH_HOME%\.agent-presets\exmachina"
   （未设置 DSH_HOME 时为 %USERPROFILE%\.dsh\.agent-presets\exmachina；目录名必须是 exmachina。
   若该目录已存在，先向用户确认是否覆盖。）
2. 通过 agentPresets 服务的 standingKeyFor("exmachina") 做真实挂载验证，报告 OK 或失败原因。
3. 验证通过后告知用户：新开会话，在预设选择器选择「机械智能」，确认工具目录含 subagent 与 subagent_fork。
注意：预设根在会话工作区之外，写入被沙箱拒绝时按正规流程单次升级并说明理由，属预期。
```

说明：预设 id 即目录名，仓库可直接克隆为预设目录（`skills/` 随克隆就位）。更新已安装的预设：在该目录 `git pull` 后，新会话自动使用新编排；已运行会话保持其启动时的编排不变。

### 方式 B — 脚本安装（人类执行）

```powershell
git clone https://github.com/KurohaneKaoruko/DSH-ExMachina.git
cd DSH-ExMachina
.\install.ps1
```

### 方式 C — 手动复制

把仓库全部内容复制到 `%USERPROFILE%\.dsh\.agent-presets\exmachina\`（`README.md`、`install.ps1`、`.git` 可留可删）。

### 验证

1. 重启 DSH 或新开会话，预设选择器出现「机械智能」。
2. 新开一个该预设的会话，工具目录包含 `subagent` 与 `subagent_fork`。
3. 交给它一个多阶段开发任务，观察是否先收拢边界、再按职能卡并行分派子代理。

### 卸载

删除 `%USERPROFILE%\.dsh\.agent-presets\exmachina\` 目录。已运行的会话保持其启动时的编排，不受影响。

## 依赖与边界

- 组合基座为 DSH 官方 `standard` 预设；`subagent` / `subagent_fork` 依赖宿主组合中的 subagents 注册表，预设只贡献委派工具与协议。
- `workflow` 与 `ralph` 仅在用户明确要求时使用，与运行时工具描述的门控一致。
- Codex / Claude Code 原生子代理行默认停用；需要时按 DSH 文档安装对应 Bundle 后取消对应行的 `disabled`。
